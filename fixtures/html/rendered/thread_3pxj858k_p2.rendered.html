And I suspect that would largely be because the page/data structure changes requiring fare more maintenance than initially envisaged. That was certainly one of the main reasons I abandoned my call cost calculator calculator/comparison . Using LLM *should* greatly reduce that maintenance headache.

samuria writes...

Some providers do 28 days and some do 30 days. Do you happen to know the frequency Launtel processes monthly payments? Is it actually daily or are they 28/30 days?

For comparison purposes it shouldn't matter how frequently, it should only matter if advertise as say 28 day prices rather than monthly as that's where the gotcha's are for consumers. And if a provider does day they bill per 28 days instead of monthly then you should give gross-up the figure to monthly so that it's then a true apples-to-apples comparison against all providers, like you do with launtel.

Eragus writes...

I think multiplying by 365/12 or 30.42 would be more accurate.

I agree, it's what people *should* be expecting for closest apples-to-apples comparison.

samuria writes...

Do you think it would make sense to base the TCO figure on the current promo deal or the price without the promo?

I would say you would have to include both because you'll have a mix of people that are only interested in short term, so the promo TCO is important, and others in longer term where non-promo is important.

Suggestions:

  • The After Promo column should be renamed as it could also be interpreted as "after the promo ends", call it "Promo Price"
  • The After Promo price should be blank if there is a actually no promo.
  • Promo column on main tab does not sort.
  • Promo/Deal column name should be consistent on both tabs.
  • Any reason why Saving column is not on both tabs?
  • Maybe add marker if VoIP as available. That for me for example could be an important deciding factor.
  • Consider making provider link to their plan page not just their NBN page.
  • Consider making plan name a link the appropriate Critical Information Summary.
  • Consider a way to select multiple providers in the filter. I generally have either a provider shortlist coming in or develop one as I research.
  • 10MATE Performance Plus plans are actually 2 month contracts as per CIS not really no-contract.
  • Launtel isn't showing nbn® 250/100
  • The dropdown provider list shouldn't contain providers you haven't scraped yet. But if it does it should be clear that there is no data yet.
  • Consider adding the ability to bookmark with the current filters set. That's what I did when I created a VoIP call cost calculator.
