## Hard rules
1. **Thread IDs are strings** (`3rvvvlwj`). Anything that parses them as integers is a bug.
2. **Parse the raw fixtures, not the rendered ones.** The live site serves `span.pages[data-pages]` for page counts and inline `var thread_pages = N;` on thread pages; JavaScript rewrites both.
3. **Whims are gone.** Do not build a Whims feature; "Private Messages" is forum 1 and opens in the browser.
4. **Skip `#watchbar`.** It is a hidden `.notebar.marker` inside `#replylist`. Moderator notes are `#top_notebar_public`; multi-part links are `.notebar.parts`.
5. **API dates** are `yyyy-MM-dd'T'HH:mm:ssxx` (`+1000`, no colon). API titles are HTML-escaped. `WATCHED.UNREAD` is an int, `THREADS.UNREAD` a boolean. Always pass `watchedmode` explicitly.
6. **The dev machine cannot reach Whirlpool** (Cloudflare blocks curl/OkHttp-from-desktop/headless). Live checks run on Dallin's phone; captures run through `tools/capture/`. Unit tests never touch the network.
7. **Releases come only from the tag-driven GitHub Actions workflow** (PLAN.md §6). Never publish a local build.
8. Nothing from `reference/` is copied into the new code; it is read for behaviour only.
9. **`main` is protected**: no direct pushes (admins included), linear history, CI job `build` must pass on an up-to-date branch. Work on a branch, open a PR with `gh pr create`, merge with `gh pr merge --squash --auto`. Release tags (`vX.Y.Z`) are still pushed directly, from a commit on `main`.

## Phase 2 (done: v0.1.0 released 2026-10-21)
What each task built and decided (PRs #2–#13):
1. **Navigation shell** (done): drawer in `app/navigation/` (`WhirlApp`, `Drawer`, type-safe `Routes`), About screen. Setup is no longer a NavHost destination: `MainActivity` shows `SetupScreen` while `setupDone` is false and `WhirlApp` otherwise, so finishing setup or signing out swaps the tree and the homepage is always the root of the back stack. "Latest activity" (`get=threads`, site-wide) is a drawer entry and a `Homepage` option (new; not in 2.14.12). Screens that can be drawer roots or pushed take a `NavIcon` (`:core:ui`). `openInBrowser` (Custom Tabs, `androidx.browser`) is in `:core:ui`. Drawer screens not built yet show a placeholder.
2. **Thread page cache** (done): Room **v2** via `AutoMigration(1→2)` adds `thread_pages` + `posts` (FK cascade); `MigrationTest` runs `MigrationTestHelper` under Robolectric (schemas are wired into unit-test assets in `core/database/build.gradle.kts`, so a new schema version must be built once before its migration test can see the JSON). `ThreadPageRepository` (`:core:data`): `page()` flow + `load(id, page|LAST_PAGE, filter, forumId, force)` returning the resolved page; LRU of 50 pages by `accessed_at`; pages refetch when older than `MaxAge.THREAD_PAGE` (1 min, our choice; 2.14.12 never cached pages); filtered pages (`PostFilter`) cache apart; parser exceptions other than `WhirlpoolError` become `Drift`. `Refresher` also takes a `lastFetched` lambda for data that stores its own fetch time.
3. **Thread lists** (done): `:feature:threadlist` owns `ForumRoute` (feature modules own their routes; the app maps callbacks via `ThreadListNav`). Screens: Latest, Recent, Watched (Unread/All tabs, "N unread"), Popular (page sections), Forum (pager over pages, group picker, "Page N of M" slider dialog, unread overlay from `get=threads&forumids=&threadcount=100`, switches to the API list when the forum is or turns out private). Shared `ThreadListBody`/`ThreadRowItem` (sticky tint; closed/moved/deleted labels; long-press: jump to last post, open in browser, go to forum). Data: `ForumThreadsRepository`, `RecentRepository` (log key per history length; `ignoreOwnRepliesRecent` hides threads whose last poster is me, as 2.14.12), `ScrapedListRepository` (forum pages, Popular, search list view; **in memory only**, like 2.14.12, newest 40 kept), `ForumRepository.privateIds` (1/35/85/134 + learned), `ThreadOpener` (PLAN.md §1.1 rules as a pure function; browser positions use `?p=N#r<replynum>` and `?p=-1#bottom`, both anchors verified in the raw thread fixture). Grouped lists order forums by first appearance (2.14.12 used a HashMap, so effectively random). `ThreadRoute` is a placeholder in `:app` until task 5. "Mark read"/"Unwatch"/"Watch" row actions are Phase 3.
4. **Forums** (done): `:feature:forums` — `get=forum` sections with Favourites first (a favourite also stays in its own section), long-press to add/remove, "Updated N ago", private forums (lock icon) open `/forum/<id>` in Custom Tabs. A private forum reached from a list header (not from this screen) still opens in-app as its API list (task 3). "New thread" is Phase 3.
5. **Thread view** (done): `:feature:thread` owns `ThreadRoute(threadId, page|-1, scrollToPost, scrollToReply, forumId, userId)`. `ThreadViewModel` shows the cached page at once (`lastKnownPage` for `-1`), then loads; a stale cached "last page" moves the pager when `?p=-1` resolves later. Bodies are parsed with `PostBodyParser` off the main thread; `PostBodyView` (`:core:ui`) renders blocks (quote attribution → `openQuote`, `wcrep1`/`wcrep2` colours, tap-to-reveal spoilers, lists, code, image placeholders that open in the browser). Moderator note and parts render above the posts; hidden posts show the reason. Post filters (all/mine/mods/reps, and "posts by X" from the post menu) cache apart. Quotes: same page → scroll; else `ThreadPageRepository.locate(replyId)` (reply locator) → same thread moves the pager, other thread opens. Links go through `WhirlpoolLink.parse` (`:core:data`): thread/archive/forum/user/reply-locator in app, whrl.pl resolved by following the redirect (`WhirlpoolWeb.resolve`), the rest to Custom Tabs. Anchors: `#r<n>` is a post number below 1,000,000, else a reply id (both forms occur in the raw markup). Browser URLs: reply to post `?action=reply&r=` (in markup), reply to thread `?action=reply&t=` and edit `?action=edit&e=` (2.14.12's, unverified). `page()` reads posts when the page row changes (combining two flows briefly showed empty pages). Watch/mark read from the thread and auto-mark-read are Phase 3.
6. **News, search, user** (done): `:feature:news` (API list grouped by local day: Today/Yesterday/weekday/date; items open `whirlpool.net.au/news/go.cfm?article=<id>`). Search lives in `:feature:threadlist` (`SearchRoute`): title search in **list view** (`o=list`, the popular-style table, sections by forum), scoped to the forum/group it was opened from (chip to widen), opened site-wide from the Forums screen; the list view has no usable page count (its `select[name=p]` options are all `0`), so Previous/Next step pages while a page is full (100 rows). Relevance view not built (optional). Private forums hide the search action. `:feature:user` (`UserRoute`, depends on `:feature:threadlist` to reuse rows): "About this user" lines and recent activity; `UserRepository` keeps profiles in memory (newest 20). No placeholders remain.
7. **Deep links** (done): manifest filters (no `autoVerify`; Android 12+ users enable them under App info → Open by default) for `forums.whirlpool.net.au` `/thread/`, `/archive/`, `/forum-replies.cfm`, `/forum/<digit>…`, `/user/<digit>…` (digits so `/forum/?action=reply` is never claimed and Custom Tabs never bounce back), plus Whirldroid's `whirldroid-thread://…?threadid=`. `MainActivity` is `singleTask`; `routeForLink` (`app/navigation/DeepLinks.kt`) maps via `WhirlpoolLink`; the route waits in `MainViewModel.link` until the NavHost exists (after setup) and opens above the start screen. Forum routes from links have no title, so `ForumViewModel.title` falls back to the forum list, then the page.

8. **Release** (done): device check on Dallin's phone (Android 17; Wi-Fi, mobile data and offline), fixes #10–#12, `v0.1.0` tagged from `main`, signed APK on GitHub Releases (2.3 MB). The release workflow marks every `v0.*` tag as a GitHub pre-release (`release.yml`), so it is not "Latest" and Obtainium needs "include pre-releases"; ask Dallin whether to change that.

## Phase 3 tasks (actions and notifications → v0.2), suggested order
PLAN.md §1.1–1.3 are the spec and §9 the scope. One PR per task, tests for every repository, worker and migration.
1. **Capture the action responses first** (done): `npm run actions` in `tools/capture` (`make_action_list.sh`, thread `3pxj858k`, which ends unwatched) saved `fixtures/api/api_cmd_*`. Bare envelope on success, the list reflects a command sent with `get=watched`, a new watch comes back read, a bogus id is an HTML 500. `WhirlpoolApi` needed no change beyond tests.
2. **Watch / mark read / unwatch** (done; checked on the phone 2026-10-21: Watch from the thread view, Unwatch + Undo restores the row in place and sends nothing, Unwatch without Undo reaches Whirlpool; the Undo snackbar lasts about 4 s): `WatchedRepository.perform` applies the change to the cached lists at once and sends it only when the Undo snackbar goes away (or after 15 s), so Undo never calls the API (there is no "mark unread", and re-watching marks a thread read to the end). The send is `watched*=<ids>&get=watched&watchedmode=1`, whose answer refreshes both lists; a failure rolls back and shows a snackbar. The snackbar host is app-wide (`app/navigation/WatchSnackbars.kt`) so it survives "back to list". Rows offer Watch, or Mark as read (if unread) and Unwatch when the thread is on a watched list; non-Watched lists and the thread view fetch the All list when stale (`ensureKnown`) to know. The thread view offers Mark as read/Unwatch when the thread is watched (not only when opened from Watched, a small change from 2.14.12). `watchedAutoMarkAsRead` marks read without Undo when a thread with unread posts is opened from Watched; `watchedBackToList` pops the thread after Mark as read when opened from Watched. `@ApplicationScope` (`:core:data`) is the process-wide scope for sends.
3. **Notifications** (done; checked on the phone 2026-10-21, Pixel 9 Pro XL, Android 17: permission dialog from the "blocked" line, inbox notification with buttons, tap opens Watched, Mark read clears all listed threads and the notification. Dozing: app in the background, screen off, `dumpsys deviceidle force-idle`; the overdue check waited (JobScheduler "device not dozing" constraint) and ran in the first `deviceidle step deep` maintenance window, catching a real new reply. Note: `cmd jobscheduler run -f` does not run periodic work early (WorkManager skips runs before the period ends); toggling alerts off and on enqueues fresh work, which runs at once. Fix #18: a check while notifications were blocked used to record threads as notified): new module `:core:notifications` (WorkManager 2.12.0, androidx.hilt-work 1.4.0). `NotificationScheduler` (started from `WhirlApplication`, which provides the Hilt worker factory; the WorkManager startup initializer is removed in the app manifest) keeps unique periodic work `watched-check` in step with `watchedNotify`/interval/setup-done (`UPDATE` policy, network constraint). `WatchedCheckWorker` → `WatchedNotifier.check()`: `WatchedRepository.fetchUnread()` (also refreshes the cached Unread list), `planAlert` (per-thread `notified` dates; "ignore my own replies" drops threads whose last poster is me), alert on new replies, silent refresh of a notification still showing, cancel when nothing is unread, `notified` pruned to the unread threads. One thread: its title + "N unread posts"; several: "N new replies in M threads" + inbox lines. Buttons go through `NotificationActionReceiver` → `WatchedNotifier.act` (`perform(..., undoable = false)`, which waits for the send). Tap opens Watched (`EXTRA_OPEN_WATCHED` on the launch intent). The permission prompt lives in `NotificationOptions` (setup and settings): turning alerts on asks first; a blocked state links to the system settings. Was: WorkManager periodic work at `notifyIntervalMinutes` (min 15), one `get=watched&watchedmode=0` call, notify only for threads whose `LAST_DATE` is newer than what `notified` holds (and, with `ignoreOwnRepliesWatched`, whose last poster is not the user); inbox style, "N unread posts"/"N new replies in M threads", actions Mark read and Unwatch (receivers that call the API and update the notification), channel for watched threads, tap opens Watched, cancel when nothing is unread. `POST_NOTIFICATIONS` prompt (Android 13+) when the setting is turned on (and in setup); re-schedule on setting change; WorkManager survives reboot. Test the worker with `work-testing`; on the phone check with it dozing (`adb shell dumpsys deviceidle force-idle`).
4. **Posting in the browser** (done): "New thread in browser" in the forum screen's overflow opens `WhirlpoolUrls.newThread` (`/forum/?action=newthread&f=<id>`). Logged out, `newthread` and `reply&t=` answer with the "Not signed in" page while an unknown action is a 404 (headed capture 2026-10-21), so both actions exist; what they show logged in is for Dallin's browser to confirm.
5. **Dark at night live switch** (done): `rememberIsNight` in `MainActivity.kt` re-evaluates at the next window edge (`untilNextEdge`, plus 0.5 s) and on every resume (a timer can run late while the phone sleeps).
6. **Release v0.2** (CHANGELOG and checklist written; tag after Dallin's checklist pass): device checklist v0.2 section with Dallin, `## v0.2.0` in CHANGELOG.md, ask before tagging.
